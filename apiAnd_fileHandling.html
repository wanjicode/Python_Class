Part 01
File Handling — Reading & Writing Files
Why Files Matter in AI Engineering
20 mins
💡 Think of it this way
Everything you've built so far lives and dies when your script runs. The moment it stops, your data is gone. Files are how you make data persist — save results, load inputs, store logs. In AI automation, you'll constantly be reading documents to send to an AI, and writing AI responses back to files. This is the skill that turns a one-time script into a real tool.
Python opens files using the open() function. You always specify two things: the file path and the mode — what you want to do with the file. Always use the with keyword when opening files — it automatically closes the file when you're done, even if something goes wrong.
ModeWhat it doesFile must exist?
"r"Read only — can't modifyYes — error if not found
"w"Write — creates file or overwrites existingNo — creates it
"a"Append — adds to the end without overwritingNo — creates it
"r+"Read and writeYes
file_handling.py
# WRITING a file — creates it if it doesn't exist
with open("notes.txt", "w") as f:
    f.write("Day 1: Learned variables and functions\n")
    f.write("Day 2: Learned loops and conditionals\n")

# READING a file — all at once
with open("notes.txt", "r") as f:
    content = f.read()
    print(content)

# READING line by line — memory efficient for large files
with open("notes.txt", "r") as f:
    for line in f:
        print(f"→ {line.strip()}")

# APPENDING — adds to the file without wiping it
with open("notes.txt", "a") as f:
    f.write("Day 3: Called the Claude API!\n")

# Always wrap file operations in try/except
try:
    with open("missing.txt", "r") as f:
        print(f.read())
except FileNotFoundError:
    print("❌ File not found — check the path.")

Part 02
API Keys & .env Files — Keeping Secrets Safe
Never Hard-Code Your API Key — Here's What to Do Instead
15 mins
To call the Claude API you need an API key — a secret string that authenticates your requests. The golden rule: never paste your API key directly into your Python code. If you push that code to GitHub, your key is exposed to the entire internet and anyone can use it at your expense. Instead, you store it in a .env file — a hidden file that never gets committed to GitHub.
  • 1
    Go to console.anthropic.com, sign in, and create a new API key. Copy it — you only see it once.
  • 2
    Create a file called .env in your project folder (the dot at the start makes it hidden on Mac/Linux).
  • 3
    Add your key to the file in this format — no quotes, no spaces around the equals sign.
  • 4
    Create a .gitignore file and add .env to it so Git never commits your secrets.
  • 5
    Use python-dotenv in your script to load the key — then read it with os.environ.get().

ANTHROPIC_API_KEY=sk-ant-your-key-goes-here

load_key.py — how to read your key safely
import os
from dotenv import load_dotenv

# Load the .env file into memory
load_dotenv()

# Read the key — never print this in real code!
api_key = os.environ.get("ANTHROPIC_API_KEY")

if not api_key:
    print("❌ No API key found. Check your .env file.")
else:
    print("✅ API key loaded successfully.")
⚠️ Critical Security Rule
Never print your actual API key. Never paste it into your code. Never commit your .env file. If you accidentally expose a key, go to console.anthropic.com immediately and delete it, then create a new one. Treat your API key like a password.

Part 03
Your First Claude API Call
How an API Call Works — The Full Picture
15 mins
An API call is just your Python script sending a message to a server and getting a response back. With the Claude API you send a message (your prompt), and the server runs Claude and sends back the response. Everything travels as a dictionary — the request is a dict you build, the response is a dict you read. Everything you've learned about dictionaries is about to become real.
Your Script
builds the request
→
API Key
authenticates you
→

runs the model
→
Response Dict
back to your script
The response comes back as a nested object. Here's what the important parts look like — notice how it's the same nested structure you learned in the Dictionaries session:
RESPONSE OBJECT STRUCTURE
response {
  "id": "msg_abc123..." ← unique message ID
  "model": "claude-sonnet-4-5" ← which model responded
  "content": [
    {
      "type": "text",
      "text": "The actual AI response is here" ← this is what you want
    }
  ],
  "usage": {
    "input_tokens": 25, ← tokens you sent
    "output_tokens": 142 ← tokens in the response
  }
}
💡 What is a token?
AI models don't read word by word — they read in tokens, which are roughly 3–4 characters each. "Hello world" is about 2 tokens. APIs charge per token, so knowing how many you're using helps you manage cost. For now, just know the number is in response.usage.
Writing Your First API Call — Step by Step
30 mins
Now you write it. Every line below is explained — read it carefully before running it. This is the most important piece of code you've written so far.
first_api_call.py
import os
import anthropic
from dotenv import load_dotenv

# Step 1 — Load your API key from .env
load_dotenv()

# Step 2 — Create the client (your connection to Claude)
client = anthropic.Anthropic(
    api_key=os.environ.get("ANTHROPIC_API_KEY")
)

# Step 3 — Send a message and get a response
response = client.messages.create(
    model="claude-haiku-4-5-20251001", # fastest & cheapest model
    max_tokens=1024, # max length of response
    messages=[ # a list of message dicts
        {
            "role": "user",
            "content": "In one sentence, what is AI engineering?"
        }
    ]
)

# Step 4 — Extract the text from the response
ai_reply = response.content[0].text

# Step 5 — Print it
print("Claude says:")
print(ai_reply)
print(f"\nTokens used: {response.usage.input_tokens} in, {response.usage.output_tokens} out")

The AI Journal Summariser
File handling + Claude API + everything you know — 40 mins
You're going to build a real AI-powered tool. It reads a text file you've written, sends the contents to Claude, and asks it to summarise and reflect on your learning progress. Then it saves the AI's response to a new file. This is a complete AI automation pipeline — input file, AI processing, output file. A real thing that real AI engineers build.
journal_summariser.py
import os
import anthropic
from dotenv import load_dotenv
from datetime import datetime

load_dotenv()
client = anthropic.Anthropic(api_key=os.environ.get("ANTHROPIC_API_KEY"))

def read_journal(filepath):
    try:
        with open(filepath, "r") as f:
            return f.read()
    except FileNotFoundError:
        print(f"❌ File '{filepath}' not found.")
        return None

def summarise_with_claude(journal_text):
    print("⏳ Sending to Claude...")
    try:
        response = client.messages.create(
            model="claude-haiku-4-5-20251001",
            max_tokens=1024,
            messages=[{
                "role": "user",
                "content": f"You are a supportive coding mentor. Read this student's learning journal and give them: 1) A short summary of their progress, 2) What they should be proud of, 3) One clear recommendation for what to focus on next.\n\nJournal:\n{journal_text}"
        }]
        )
        return response.content[0].text
    except Exception as e:
        print(f"❌ API error: {e}")
        return None

def save_summary(summary, output_path):
    timestamp = datetime.now().strftime("%d %b %Y %H:%M")
    with open(output_path, "w") as f:
        f.write(f"AI Mentor Feedback — {timestamp}\n")
        f.write("="*40 + "\n\n")
        f.write(summary)
    print(f"✅ Saved to '{output_path}'")

# --- Run the pipeline ---
journal = read_journal("my_journey.txt")

if journal:
    summary = summarise_with_claude(journal)
    if summary:
        print("\n--- Claude's Feedback ---")
        print(summary)
        save_summary(summary, "ai_feedback.txt")
