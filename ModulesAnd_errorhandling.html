Modules & Importing
What is a Module? Why Not Write Everything Yourself?
15 mins
💡 Think of it this way
Python comes with a massive toolbox of pre-built tools — but they're not loaded by default, because you don't always need all of them. A module is one drawer in that toolbox. When you need it, you open it with import. Why write your own random number generator when Python already has a perfect one? Why write your own date calculator? Someone else already did it. You just import it and use it.
There are three kinds of modules you'll use: built-in modules that come with Python (no installation needed), third-party packages that you install with pip, and your own modules — Python files you write yourself that you import into other files. Today we focus on the first two. The third one you're already doing every time you write a .py file with functions.
random
Random numbers, choices, shuffling
math
Square roots, powers, pi, floor/ceiling
datetime
Current date & time, date maths
os
File paths, environment variables, system info
json
Read and write JSON data ← used with every API
time
Pausing scripts, measuring how long code takes
modules_intro.py
# Three ways to import

# 1. Import the whole module
import random
print(random.randint(1, 10)) # random number 1–10
print(random.choice(["Python", "AI", "APIs"])) # random item from list

# 2. Import just what you need (cleaner)
from math import sqrt, pi
print(sqrt(144)) # → 12.0
print(round(pi, 4)) # → 3.1416

# 3. Import with a shorter alias (very common with big packages)
import datetime as dt
today = dt.date.today()
print(f"Today is: {today}")

# os — useful for environment variables (API keys live here!)
import os
print(os.getcwd()) # prints your current working directory

💡 Why os is important for AI engineering
When you call an AI API, you'll need a secret key — called an API key. You never hard-code it directly in your script (that's a security risk). Instead, you store it as an environment variable and read it with os.environ.get("API_KEY"). The os module is how you do that. You'll use this in the very next session.

Part 02
Error Handling — Writing Code That Doesn't Crash
Reading Errors — They're Helping You, Not Attacking You
15 mins
💡 Think of it this way
An error message is Python's way of pointing at exactly where things went wrong and why. Most beginners panic when they see a red wall of text. But once you learn to read it, an error message is the most useful thing Python can tell you. It's not a failure — it's a very specific hint about what to fix.
Every Python error has three parts. Learn to find these three things and you can debug almost anything.
WHERE
File "calculator.py", line 12, in divide
← the file name and line number where it crashed
WHAT
ZeroDivisionError
← the type of error — search this on Google if unsure
WHY
division by zero
← the human-readable explanation of what went wrong
ValueError
Wrong type of value — e.g. int("hello")
TypeError
Wrong type used — e.g. "5" + 5
KeyError
Dict key doesn't exist
IndexError
List index out of range
FileNotFoundError
File path doesn't exist
ZeroDivisionError
Dividing by zero
Try It — Deliberately Cause Errors
In a new file, write code that causes each of these errors one at a time: try int("hello"), try adding a string and a number, try accessing my_list[100] on a short list. Read the full error message each time. Identify the WHERE, WHAT, and WHY. Getting comfortable with errors is one of the most important skills you can build.
try / except / else / finally — Catching Errors Before They Crash
25 mins
Now that you can read errors, here's how you handle them without crashing. The try/except block says: "try this code — if something goes wrong, don't crash, run this instead." This is essential for any real program that takes user input, reads files, or calls APIs — because all of those can fail in ways you can't predict.
try: run this code
↓
ERROR occurred
↓
except: handle the error
NO error
↓
else: runs only if no error
↓
finally: always runs, no matter what
try_except.py
# Basic try/except — stop a crash from a bad input
def safe_divide(a, b):
    try:
        result = a / b
    except ZeroDivisionError:
        print("❌ Can't divide by zero!")
        return None
    else:
        print(f"✅ Result: {result}")
        return result

safe_divide(10, 2) # → ✅ Result: 5.0
safe_divide(10, 0) # → ❌ Can't divide by zero!

# Catching multiple error types
def safe_input_number():
    try:
        num = int(input("Enter a number: "))
        return num
    except ValueError:
        print("❌ That's not a valid number. Try again.")
        return None

# Catching ANY error — use sparingly
def safe_api_call():
    try:
        # imagine an API call here
        pass
    except Exception as e:
        print(f"Something went wrong: {e}")
    finally:
        print("API call attempted.") # always runs
⚠️ Don't Catch Errors You Don't Understand
It's tempting to write except Exception everywhere to silence all errors — but this hides real bugs. Always catch the specific error type you expect. Only use except Exception as e as a last resort, and always print e so you can see what went wrong.

The Unbreakable Quiz
Modules + Error Handling + Everything Before — 40 mins
Remember the quiz game you built earlier? You're going to rebuild it — better. This version uses random to shuffle the questions, datetime to timestamp the result, and try/except to make sure no bad input can ever crash it. A quiz that cannot be broken no matter what the user types.
unbreakable_quiz.py
import random
from datetime import datetime

questions = [
    {"q": "What keyword defines a function in Python?", "a": "def"},
    {"q": "What data structure uses key-value pairs?", "a": "dictionary"},
    {"q": "What loop runs while a condition is True?", "a": "while"},
    {"q": "Which company makes Claude AI?", "a": "anthropic"},
    {"q": "What command installs Python packages?", "a": "pip"}
]

def run_quiz(name):
    score = 0
    shuffled = random.sample(questions, len(questions))

    print(f"\nHey {name}! {len(shuffled)} questions. Let's go.\n")

    for i, item in enumerate(shuffled):
        try:
            answer = input(f"Q{i+1}: {item['q']} ").strip().lower()
        except Exception as e:
            print(f"Input error: {e}. Skipping.")
            continue

        if answer == item["a"]:
            print("✅ Correct!\n")
            score += 1
        else:
            print(f"✗ The answer was: {item['a']}\n")

    return score

def main():
    try:
        name = input("Enter your name: ").strip()
        if not name:
            name = "Coder"
    except Exception:
        name = "Coder"

    score = run_quiz(name)
    total = len(questions)
    timestamp = datetime.now().strftime("%d %b %Y, %H:%M")

    print(f"--- Result for {name} | {timestamp} ---")
    print(f"Score: {score}/{total} ({round(score/total*100)}%)")

main()
